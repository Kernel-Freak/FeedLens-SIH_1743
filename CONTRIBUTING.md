# Contributing to FeedLens

First off, thank you for considering contributing to FeedLens! We welcome contributions from the community to help make this tool even better for digital investigators.

This document provides guidelines for contributing to the project. Please read it before submitting issues or pull requests.

## Code of Conduct

This project and everyone participating in it is governed by a [Code of Conduct](CODE_OF_CONDUCT.md). *(Optional: Create a CODE_OF_CONDUCT.md file or remove this link if you don't have one yet)*. By participating, you are expected to uphold this code. Please report unacceptable behavior.

## How Can I Contribute?

There are several ways you can contribute:

* **Reporting Bugs:** If you find a bug, please let us know!
* **Suggesting Enhancements:** Have an idea for a new feature or an improvement to an existing one?
* **Submitting Code Changes:** Want to fix a bug or implement a feature yourself?

### Reporting Bugs

Before submitting a bug report, please:

1.  **Check the [existing issues](https://github.com/Kernel-Freak/FeedLens-SIH_1743/issues)** to see if someone has already reported the bug.
2.  If not, **create a new issue**.
3.  **Clearly describe the issue:**
    * Provide steps to reproduce the bug reliably.
    * Describe the expected behavior and what actually happened.
    * Include details about your environment (Operating System, Python version, Browser version, FeedLens version if applicable).
    * Include any relevant error messages or screenshots.

### Suggesting Enhancements

1.  **Check the [existing issues](https://github.com/Kernel-Freak/FeedLens-SIH_1743/issues)** (and potentially [discussions](https://github.com/Kernel-Freak/FeedLens-SIH_1743/discussions) if enabled) to see if your idea has already been suggested.
2.  If not, **create a new issue** (or discussion post).
3.  **Clearly describe the enhancement:**
    * Explain the problem you're trying to solve or the improvement you're suggesting.
    * Detail your proposed solution or idea.
    * Explain why this enhancement would be useful to FeedLens users.

### Submitting Code Changes (Pull Requests)

1.  **Fork the repository:** Click the "Fork" button on the top right of the repository page. This creates your own copy.
2.  **Clone your fork:** `git clone https://github.com/Kernel-Freak/FeedLens-SIH_1743.git`
3.  **Create a new branch:** Work on a separate branch for your changes. Use a descriptive name (e.g., `fix/ocr-bug`, `feature/add-proxy-support`).
    ```bash
    git checkout -b <branch-name>
    ```
4.  **Set up your development environment:** Follow the installation steps in the `README.md` to install dependencies (preferably in a virtual environment).
5.  **Make your changes:** Write your code and add comments where necessary.
6.  **Follow Code Style:** Try to adhere to the existing code style (e.g., PEP 8 for Python). *(Optional: Add specifics like "We use Black for formatting")*
7.  **(Optional) Add Tests:** If you're adding a new feature or fixing a significant bug, please consider adding tests if a testing framework is set up.
8.  **Commit your changes:** Use clear and descriptive commit messages.
    ```bash
    git add .
    git commit -m "feat: Add support for custom timestamp formats"
    # Or: git commit -m "fix: Correctly handle browser closing during scroll"
    ```
9.  **Push your branch:** Push your changes to your forked repository.
    ```bash
    git push origin <branch-name>
    ```
10. **Open a Pull Request (PR):**
    * Go to the original FeedLens repository on GitHub.
    * Click on the "Pull requests" tab and then "New pull request".
    * Choose your fork and the branch containing your changes.
    * Provide a clear title and description for your PR. Explain *what* changes you made and *why*.
    * Reference any relevant issues (e.g., "Closes #123").
    * Submit the PR!
